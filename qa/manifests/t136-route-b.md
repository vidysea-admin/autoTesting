## What changed
- `src/autotester/stages/crawl_findings.py` (new, 114 lines): the converter. First-party NETWORK issues and CONSOLE `error:` lines become `Finding(source="crawl")`, deduplicated by kind + URL (query stripped) + status, or by console text; evidence refs are `crawl/<id>/issues.jsonl#<issue id>` plus the node screenshot `crawl/<id>/shots/<ref>` when recorded. EVIDENCE (tool failures), third-party noise, NAVIGATION/OVERLAY/DIALOG (crawler state) and console warnings are never findings (X9). `crawl_findings_for` refuses an unstored crawl (`CrawlNotFound`).
- `src/autotester/schema/bench.py`: `Finding.source` (`case` default | `crawl`) and `BenchTrial.crawl_ids_scanned` (default empty; old trial files still load, tested). extra=forbid kept.
- `src/autotester/stages/bench.py::run_autotester_trial`: optional `crawl_findings`, `crawl_ids_scanned`; findings are verdict findings + crawl findings (K11a: still the only trial builder).
- `src/autotester/stages/bench_from_run.py::bench_from_run`: `crawl_ids` parameter; unknown crawl raises `RunNotUsable` before anything is written (K11b).
- `scripts/bench_from_run.py`: `--crawl <id>` (repeatable) or `--crawl all`.
- `src/autotester/schema/acceptance.py`: `ParticipantColumn.crawl_findings`, `crawl_ids_scanned`.
- `src/autotester/stages/acceptance_comparison.py`: `_column` fills them; with 0 findings AFTER a crawl scan the FP-rate Measure reads `unavailable (no reported findings: N crawl(s) scanned, 0 product issues)` (`_scanned_reason`) and `completeness_problems` accepts that one case (`_zero_after_scan`). 0 findings with no scan still fails (K8 unchanged).
- `scripts/check_acceptance_comparison.py::render`: prints `crawl findings: N, case findings: M` so the report tells them apart.
- `docs/MAP.md`: regenerated by `autotester map` (+1 line, the new module); it was already stale on the base.
- Not touched: qa/contracts, DECISIONS, qa/issues.jsonl.

Semantics worth knowing: with no human list every finding is unadjudicated, so FP rate reads 1.0 ("unadjudicated: no human list"), exactly as for case findings before. Recall and detection stay `unavailable (no human list)`.
