## Things the checker should look at (judgement calls)

1. **Unreachable cases are `RawResult(outcome=ERRORED)` that `grade` settles as INCONCLUSIVE**, not a NOT_RUN outcome. The contract asks for an INCONCLUSIVE verdict and "not ERRORED-per-case with N identical 30 s goto timeouts": the verdicts are INCONCLUSIVE and carry the ONE cause, no goto was attempted. This is the same path an exhausted budget takes (`grade_errored_result`), so the verdict path (C12) has no new branch. If you want a distinct raw outcome, that touches `schema/enums.py` and the verdict path (E2's), which is out of E4's file list.
2. **A `base_url` host outside `allowed_domains` is silently not probed and the run proceeds** (contract: "refuse, do not probe"). I read "refuse" as "refuse to connect", not "refuse to run": the gate and the browser already refuse an out-of-scope navigation per case, and failing the whole run for a project whose `base_url` is declared outside its own scope is a separate decision. Flag it if you read "refuse" as "fail the run".
3. **`acting` lives inside `Run.excluded_s`** (the dict already persisted) rather than a new `Run` field, so there is one source for the D-112 arithmetic and a pre-D-112 run (`excluded_s` None) is unambiguously NOT RECORDED. A run recorded between D-112 and E4 has `excluded_s` without `acting`; the page says "acting time NOT RECORDED" for it (pinned).
4. **The probe runs after the approval gate, the budget and the snapshot, and before the browser pool.** The gate still cannot be skipped: `target_probe` is a seam but it is consulted only after `require_live_case_approval` has passed, and an unreachable target ends the run (`skip_run`), never widens it. `tests/test_run_launcher_approval.py::PINNED_SEAMS` is an exact allow-list (its docstring: a new knob "must be argued for, with the gate still unskippable"); this is the argument, and I added `target_probe` to it.
5. **The probe resolves and connects from the server running AutoTester**, with `ProxyHandler({})`. A corporate proxy-only environment would see every target as unreachable. The deployment is Cloud Run (no proxy); if that changes, the probe needs the same proxy policy as the browser. Stated, not guarded.
6. **Three exact-key pins on `excluded_report()` were extended additively with `"acting"`** (`test_run_teardown_stall.py:212`, `test_run_teardown_stall_wiring.py:91`, `test_teardown_residuals.py:71`). No assertion was weakened: each still pins the full key set.
7. **`test_session_survives_failure.py::test_a_restart_is_a_recorded_event_not_a_silent_retry`** filters `video-lost` out of its event list. Its fake page has `video = None` with recording on, which is exactly the formerly silent path E4.3 makes loud; the test's own subject (exactly one `session-restart`, reported once) is unchanged. Mutant m17 shows the new behaviour is pinned elsewhere.
8. **Two stubs of `run_cases_traced` (`test_ui_runs.py:171`, `test_run_failure_artifacts.py:57`)** returned a `SimpleNamespace` lacking the new `ParallelPlan` fields; they now supply `stop_reason=None, warnings=()`.
9. **`report_export.py::_video_link_html` and the HTML export's bounds line are unchanged**: E4 changes the live run page; the export keeps its existing `bounds_text`. A follow-up can carry `clock_text` into the export.
10. **`routes_report.py` lost the `_video_section` helper** to `routes_video.py` (the file was 306 lines after the cards). E1 also edits `routes_report.py` (`_trace_card`, `run_view`); expect a textual merge conflict only around the two replaced lines (`:182`, `:193`).
