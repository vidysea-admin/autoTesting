## Layers, strongest first
1. Value layer: real secret values from the repo-root `.env`, `docker image inspect` Env, `docker inspect` of the container Env, and `--secrets-file` (one value per line, or KEY=VALUE). Skipped: shorter than 6, true/false/null/none/yes/no/on/off/localhost/root/admin, paths (start with `/`), plain numbers/versions, anything with localhost or 127.0.0.1. Every exact occurrence is masked under any key name, longest first. Values live in a mode-700 temp dir removed by the EXIT trap, never printed.
2. Name layer (GNU sed): PW|PASS|PWD|PASSWORD|PASSWD|SECRET|TOKEN|KEY|APIKEY|AUTH|CREDENTIAL|COOKIE|SESSION|PRIVATE as a segment or suffix (`DB_PASS`, `PATHLYNKS_LOGIN_PW`, `clientKey`, `x-api-key`), case-insensitive. Separators: `=`, `:`, `=>`, whitespace (`token x`, `the token is x`, `GEMINI_API_KEY x`), XML tags, `%3D`, `%22%3A%22`, `--password x`, `-p x`. Quoted values mask to the closing quote with JSON-escaped quotes handled; fully escaped `\"` JSON too. Also URL `user:pass@`, Authorization/Cookie/Set-Cookie headers, `?code=`, PEM, token shapes (AKIA, ghp_/gho_/ghs_/github_pat_, JWT, AIza, xox, sk-). Over-masking reduced: a tail after the name must start with `_ . -` or be `id`, so `author:`, `keyboard`, `keys=3`, `session started`, `session.py`, `ExitCode=126`, `exit code 126` and `-p 8000:8000` / `mkdir -p /path` stay readable.
3. Python layer: when python and the repo src import (`AUTOTESTER_PYTHON`, python3, python), values also go through `Redactor.scrub` (value plus percent/entity encodings) before the sed layers.
4. Fail safe: if `sed --version` is not GNU, only section headers, signature lines (Permission denied, PREFLIGHT, OOMKilled, READINESS, uid=, ...) and the DIAGNOSIS block are kept, lines with secret-looking words are withheld, a loud NOTICE goes to stderr and the log, and one "N line(s) withheld" line closes each stream. Deviation from the brief wording: this also applies when python is present but sed is not GNU, because python only does layer 1. `REDACT_NO_PYTHON=1` forces the python-less path.
5. PEM: an unterminated BEGIN masks to the end of its line plus following contiguous base64-looking lines (32+ chars); the next ordinary line (section header, READINESS) is kept.
6. Performance: one sed pass over the whole stream, no per-line loop and no leading unbounded name prefix. Measured 414 KB (with a 60 KB single line, `key=` x 15000, and 1200 realistic secret-bearing line groups) in 0.6 s on this machine; the test asserts < 10 s, timed inside bash.

## Limits
- Needs GNU sed for the name layer (CI and Git Bash have it); BSD/macOS takes the fail-safe path, which was tested only with a fake non-GNU sed.
- Unquoted multi-word passwords (`password: a b c`) mask only the first word; `-p x` skips values starting with `/`, `.` or all-digit/colon (ports), and an unquoted value starting with `<`, `>` or a backslash is not masked.
- A PEM-looking run of 32+ char base64 lines directly after a BEGIN marker is masked even if it is not key material.
- Not verified here: a real docker run, real Cloud Run log shapes.

## Cycle 2 (fixes the cycle-1 FAIL: awk .env parsing diverged from python-dotenv)
- .env values now come from the repo's own parser: `redact_cli --values-from-env FILE` prints `dotenv_values(FILE)` values (the parser `core.env.load_repo_env` uses), one line each (a multiline value prints each line), to a pipe into `_redact_load`; never argv. `_redact_env_load` runs it for the repo-root `.env` and `--secrets-file`, together with the awk reader; the UNION is masked. A failing dotenv reader prints a NOTICE to stderr; the awk values still load.
- The awk reader (`_redact_assignments`, the only reader without python) is dotenv-compatible: optional `export`, spaces around `=`, single/double quotes with escapes, multiline quoted values, unquoted values end at whitespace+`#`. It over-emits: each value raw (trimmed) and comment-stripped/unquoted/unescaped. `KEY=` (empty) loads nothing and keeps the key readable.
- Temp files are 0600: `umask 077` in main before `mktemp -d`, and `_redact_load` / the python buffer run under `umask 077` subshells.
- If `redact_cli` (the filter) fails, `redact` prints a NOTICE (stderr) and a `[NOTICE: python redaction failed ...]` line, and that block goes to the fail-safe (value sed first when GNU sed exists). Never raw text, never silent empty output. The block is buffered in the 0700 values dir and removed after each call.
- Split: `scripts/container_diagnose_lib.sh` (253 lines: redaction + `diagnose`, sourced) and `scripts/container_diagnose.sh` (153 lines: usage, `_sec`/`_run`, `main`). Tests source the lib. `.github/workflows/container-smoke.yml` paths (and its test) gain the lib so a lib change triggers the smoke job.
- New tests: dotenv parity of `env_values`; the three leak forms plus `export`, multiline, `KEY=` and single-quoted+comment, masked in free text on the awk path and on the python path; the python path really calls dotenv; redact_cli failure gives NOTICE + fail-safe with no leak and no leftover buffer; 0600 temp files (static umask-order check always; the mode check is skipped where the filesystem ignores umask, as on this Windows host); main and lib each <= 300 lines, LF, `bash -n`.
- Limit: the runtime 0600 mode assertion was not observed on this host (NTFS ignores umask); it runs on Linux.
