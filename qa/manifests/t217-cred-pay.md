## Judgement calls for the checker
1. **Two schema files outside OG-CRED's two stage files.** The declaration shapes must live in `schema/` with `extra="forbid"` (CLAUDE.md design rules), so `schema/credential_policy.py` and `schema/payment_path.py` are new, uniquely named and cannot collide with another group's files. Several small models per file (as T-211/T-212 judged); closed vocabularies are defined there, not in the enums file.
2. **Declarations are files in the run dir.** `OracleContext` has no field for per-oracle configuration, and it is T-211's. CORE-REQUEST: `src/autotester/schema/oracle_context.py` (owner T-211) add an optional `declarations: dict[str, Any]` (or the project's declared `credential_policy` / `payment_paths`) so a runner can hand an oracle its declaration instead of reading `<run_dir>/credential_policy.json` / `<run_dir>/payment_paths.json`. Until then a missing/invalid file raises `PolicyNotDeclaredError` / `PaymentNotDeclaredError` (type name only in the registry), so an undeclared project shows `errored`, not a false `ran`.
3. **Input values ride in the step text as `fill <selector> = <value>`.** `RoleStep` is `<verb> <target>` with no value field and the repo's existing repro convention is `fill role=textbox[name=Email] = a@b.test`. CORE-REQUEST: T-210's session port must treat `fill <selector> = <literal-or-{{SECRET:KEY}}>` as selector plus value. The synthetic weak value exists only in the step handed to the port; every finding says `[probe:<rule>]`. Test: no typed value appears in any serialised finding (`test_mp27_a_finding_records_the_rule_never_the_value`).
4. **Probing a reset form can change the account.** An accepted weak password on a reset/create form is a real write (allowed: `ALLOW_WRITES` follows the supplied account, D-018/D-053, not re-litigated here). The declaration may carry `restore_steps`, run right after an accepted probe and never after a rejected one; a failed restore is said in the finding title ("account not restored"). Probes per run are capped (<= 8 flows, <= 40 probes, refused at validation) and an unreachable form is tried once, not once per rule.
5. **Plain-mail half reads decided outcomes, it does not re-read the mailbox.** It looks at passed `mailbox` / `present` assertion outcomes whose `last_observation` says `N credential-shaped token(s) present` (the mailbox oracle's wording; `test_mp27_the_token_count_is_read_from_the_mail_oracles_own_wording` builds that wording through `observation_from_read` so a drift goes red). One extra IMAP read per run is thereby avoided (MP16 budget). The token count is over the whole read window, not one subject, so it over-flags rather than under-flags; `token_allowed_assertions` names the mails that legitimately carry a one-time link or code.
6. **"Reports whether each path reaches a gateway page."** The registry only carries findings, so the per-path report (`reached | not_reached | unobserved`, coupon state, step counts) is returned by `check_path` and written to `<run_dir>/payment_report.json` (states and counts only, no marker, URL or key). A path that is `reached` is a report line, not a finding.
7. **The stop is structural, not a heuristic on step text.** The gateway marker is looked at after every performed step, so a mis-declared `gateway_steps` that includes the charge click (the test declares `["click #checkout", "click #pay-now"]`) still stops after the first. A hosted-gateway "Pay now" that merely opens the gateway page is legitimate and is not refused by name. Provider test mode is the one declared exception, and the schema refuses `test_mode_steps` without it.
8. **An unobserved page is never `not_reached`** (SA9 spirit, as the mailbox oracle): a lost observation gives `unobserved`, no finding, and `PaymentUnobservedError` when nothing else was proven; proven findings from sibling paths are kept.
9. **`run` is an alias** (`run = credential_findings`, `run = payment_findings`) for the same reason as T-212 (doctor's duplicate-concept rule vs `doctor.py::run`). CORE-REQUEST (unchanged): `doctor.py` exempt `stages/oracle_*.py::run` after the doctor-oracle-exempt unit merges.
10. **Pass-by-name of rule values.** A finding's `finding_id` is `cred-<flow-id>-<rule>` and its title names the rule; `MultiRoleFinding` has no rule field (T-209's schema, not edited).
11. `autotester doctor` reports 2 violations, both stale-generated (docs/MAP.md, docs/SNAPSHOT.md); not hand-edited, the merge-queue owner regenerates. `uv run ruff check src tests scripts` passes.
