Cause: routes_role_accounts.py:213-233 (`_merged` / `merge_by_id`) replaces an account by id, `_refs_for` (role_onboarding.py:83) rebuilds its `SecretRef` scope from the new platform, and `_require_credentials_edit` (:215) fires only when a value is submitted. A later run would type the stored secret on the attacker's host, the credential exfiltration AU21 exists to stop. MP6 (b) lets `project.edit` declare keys; it does not let it re-scope a key that already holds a stored value. Fix direction: when a submission changes the platform, scope or `include_subdomains` of an already-declared key (diff `project.secrets` against `refs` for keys in both), require `credentials.edit` before saving, and add a fixture for it. issue: P1
