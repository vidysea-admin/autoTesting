## Findings (numbered)
1. **Warning - M16 stays OPEN after this PASS; a follow-up unit is needed.** U3a moved only the sites the existing public API covers. Sections A and B of the manifest (about 60 `exists` / `glob` / `iterdir` / `stat` / `unlink` / raw-read sites, e.g. `orchestrate_downstream.py:49,92,148`, `orchestrate_execute.py:203`, `unified_report.py:152`, `grade.py:224`, `video_retention.py:82`) cannot move until U4 adds `exists_path` / `list_children` / `mtime_path` and a delete primitive. Until then a Mongo run would write a state document to the store and test for it on disk. Contract ordering risk ("U3 lands before U4 is switched on", M16) therefore still holds: the dispatcher should add a unit (U3d) after U4 for sections A, B and failure_bundle, and must not flip any area to mongo before it passes. Not a defect of this unit; the dispatcher narrowed the scope, the manifest says so plainly, and the file backend is the only one wired (`filestore._backend`).
2. **Warning - F1 (judged): revert `real_acceptance.py:166` to the raw write; `acceptance_baseline.py:127` stays.** `write_evidence` writes `<root>/qa/evidence/t169-real/<mode>/{evidence.json,comparison.json,checklist.md}` where `root` is the repo root (`scripts/run_real_acceptance.py:112`, `drive_real(client, store, spec, seams, root, ...)`). These files are checked-in human-review evidence (`qa/manifests/t169-real-driver.md:10`), not run state, and the path is not one the M16 rule names (`ProjectPaths`, `team_path`, `repo_root()/".work"`). Routed through `filestore`, the key `qa/evidence/t169-real/...` falls to area `projects` (`filestore.area_of`, `filestore.py:186-191`), and U4's route table is closed (M6): a Mongo `projects` area would refuse or swallow them, so the evidence would stop landing in git. `out.mkdir(...)` at `real_acceptance.py:145` is still a raw local mkdir, so the code would also leave an empty local folder. In file mode the output is byte-identical (differential above), so this is not a FAIL. Recommend: one-line revert to `(out / name).write_text(text, encoding="utf-8")` plus an entry in U3c's doctor allow-list; it then needs a `LEFT` row in `tests/test_sweep_u3a.py`: `"stages/real_acceptance.py": {"write_text": 1}`). `acceptance_baseline.py:127` is fine: it writes under a new standalone `destination` root, in the same `ProjectStore(project.slug, root)` as the `save_project` / `add_source` calls beside it that already go through `filestore`, so it is consistent with them and outside `repo_root()` in practice (plain file, `_route`).

Strictly safer; pinned by `test_a_corrupt_drive_job_reads_as_absent` and `test_a_payment_declaration_and_a_credential_policy_load_through_the_backend`.
4. **Accept - F5 (temp name).** Old: fixed `<id>.tmp` (two concurrent writers collided on it); new: `_atomic_write` unique `.tmp-*` (`filestore.py:68-78`). Nothing reads or globs the old name: `git grep "drive-jobs\|drive_jobs" -- src` shows only `routes_intake.py:24` using `load_job` / `save_job` / `effective_state`; no `.tmp` consumer.
