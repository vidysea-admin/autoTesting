Probe output: `approve --standing` -> `appr_264de840ddbc ... STANDING`; UI revoke 200; second identical `approve --standing` -> exit 0 and the SAME `appr_264de840ddbc`, `list_approvals()` length 0 afterwards, grants file has 2 rows. This is a fail-closed direction (nothing is wrongly honoured) but it is exactly the "green grant that the gate refuses" shape CN4 calls out (AT-145/AT-147). It pre-exists for dated grants but the new first-class Revoke button makes it likely. The UI path is not affected (it stamps `datetime.now(UTC)`).

Consider `standing == "1"` (or the same truthiness helper the form uses elsewhere). Not a security failure: standing is restricted to crawl and the per-run caps still apply.
