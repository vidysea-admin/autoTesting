2. **Warning (no data effect): apply and verify disagree on a drifted account.** `auth/migrate_auth.py:89-90` `_import_users` calls an account `unchanged` when the stored row has the same id and email, ignoring `password_hash`, `generation`, `disabled`; `auth_status` (`migrate_auth.py:142-144`, used by `--check-remote` and `verify`) compares all four. Probe: target hash edited, then `migrate --apply` reports `auth_users unchanged=3` exit 0, while `verify` reports `conflicting-id=1`, `mismatches: 1`, exit 1. Nothing is overwritten (M42 holds) and verify (M44) catches it, so not a block; recommend `_import_users` use the same comparison so apply says `conflicting-id` too.
3. **Fragility flag judged: acceptable, with a follow-up.** `auth/migrate_auth.py` uses `MongoAuthTx`/`MongoTxBase` underscore helpers (`_docs`, `_one`, `_get`, `_writer`, `_insert`, `_patch`, `_drop`, `_allocate` in `auth/store_mongo_tx.py:86-167`, and the static `_grant`), plus public `known_user_ids`, `has_session`, `insert_session`. It is the same `auth` package, it goes through the journalled `transaction()` rather than raw collections (the correct door, M29), and a rename by u6bf would break 15 tests at once rather than corrupt silently (`test_a_failed_import_is_undone_whole`, `test_the_import_goes_through_the_lease_and_leaves_no_journal`). Not a block. Follow-up for the u6bf owner: give `MongoAuthTx` a public bulk-import method so this module stops depending on private names. Related, informational: `_import_groups` (`migrate_auth.py:73-77`) patches or drops seeded groups in the TARGET when the target holds no accounts yet (AU11 semantics, inside the undo journal); M42's "non-destructive" covers the source, so this is within the contract, but G1 should know apply can rename or delete default groups on an account-less target.
4. **Doc nit.** The `cli_store.py:7-8` docstring says the report never shows "a hash", while `cli_store.py:83` prints the CEO list's content hash (allowed and required by D-128). Reword to "no credential hash or secret".
5. **Doc/behaviour note, no defect.** `--only credentials` without `--check-remote` reports `to_insert=<declared keys>` even when the store already holds them (a dry run compares nothing by design, M41); only `--check-remote` or `verify` compares.
