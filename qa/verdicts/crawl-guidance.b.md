### Rulings the brief asked for
- **Role `button` whose text is a selected value, with no `aria-haspopup`** (`<div role=button tabindex=0>Class 10A</div>`, `<button aria-expanded=false>Class 10A</button>`): text is sent as the `name`. RULING: G3 does not require this to be neutralised. It is indistinguishable from any app-authored caption ("Save", "Open menu"), which G3 permits as `name` ("trimmed, scrubbed"); a button is not an input value. A caption can hold a user's name (an account menu) and G3 permits it; the scrub knows only `.env` values.
- **`aria-haspopup="menu"`** (`<button aria-haspopup=menu>Jane Doe</button>`): text sent. RULING: same as above; a menu trigger is a caption, not a value, and `menu` is correctly absent from `FIELD_POPUPS` (`enumerate.js:88`). Side effect to know: `aria-haspopup="true"` (which ARIA defines as `menu`) IS in the list, so an `aria-haspopup=true` account/menu button with no `aria-label` loses its caption and ranks as `<field:button>`. A ranking-quality cost, not a safety one.
- **`grid` / `treegrid` / `gridcell` / `tree` / `treeitem` / `td[tabindex]`** (text is cell or node content): text sent unless the control is `in_row` (a parent `role=row` / `tr` / `li` with more than 3 siblings becomes `<row item>`, `enumerate.js:145-159`; probe `gridcell-bigrows` sends `<row item>`). RULING: page content in the same class as link text, which G3 allows and defends with the `in_row` placeholder; not a data field. A grid of 3 or fewer rows is unprotected, exactly as a 3-item `<ul><li><a>Jane Doe</a>` already is. Recorded as N6, not a regression.

## NON-BLOCKING RESIDUALS (the maker may take them in one small commit; the checker rules them out of scope for this PASS)

None is a markup shape MUI, Ant or react-select emit, and the unit's crawls run on test accounts, not live users. Judgment call, stated plainly: if Umesh reads G3 as a hard wall with no residual, N1-N3 and N5 are a few lines and should be taken before G12.
- **N1** `enumerate.js:161,89-95`: elements INSIDE a `<select>` / `<datalist>` are not fields. Chromium's customizable select (`<select style="appearance:base-select"><button><selectedcontent>`) puts the SELECTED VALUE in a `<button>` descendant that `SELECTOR` enumerates and that is sent as its name; `<option onclick>` / `<button>` inside a `<select>` and `<option tabindex>` in a `<datalist>` send the option text. Fix direction: treat `el.closest("select, datalist")` as a field in `fieldLabelOf` and in `is_field`.
- **N2** `enumerate.js:106`: the `<label>`-text path strips `input, select, textarea, option` from its clone but not ARIA widgets or contenteditables, so `<label>Field <div role=combobox>VALUE</div><input></label>` sends `Field VALUE` as the input's label. Fix: also remove `[role], [contenteditable]` descendants from the clone.
- **N3** `enumerate.js:98-102`: an `aria-labelledby` target is read with `innerText` unfiltered, so a target wrapper that contains a different `<select>` sends all its option texts (`Name <all options>`). Fix: strip field descendants from the target text, as for N2.
- **N4** `enumerate.js:98-102`: an `aria-labelledby` pointing at a sibling element that merely displays the value sends that text. Inherent: a labelledby target IS the accessible name and cannot be filtered without breaking real labels. Not recommended.
- **N5** `enumerate.js:91`, `explore_guidance_payload.py:70`: only the FIRST role token is read, so an ARIA fallback list (`role="foo combobox"`) escapes. Fix: take the first token that is in `FIELD_ROLES`.
- **N6** Carried and ruled: path-segment PII and opaque tokens survive `href_path` (`/users/x%40y.com/edit`, base64 reset tokens, JWT-shaped segments); G3's letter ("href path only") is met, so not counted (cycle-2 observation a). A grid or list of 3 or fewer rows is not `in_row`-protected (see rulings). A `role=button aria-label="Remove <selected value>"` (react-select multi) would be sent if enumerated; it needs `tabindex` or `onclick`, which react-select does not set, so it was not enumerated in a real library. Cycle-1/2 observations c-g (per-call cap vs wall clock, reuse key, `inf` bounds) are untouched by this delta.
