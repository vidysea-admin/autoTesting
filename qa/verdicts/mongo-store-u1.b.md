## Findings that block PASS

**F1 (M4(c), CRITICAL) - the URI-path clash check does not match the driver's database parse.** `src/autotester/store/mongo_guard.py:204-210` (`_uri_path_database`: `urlsplit`, `unquote_plus`, no `.collection` split) is called at `:229`. The contract falsifier is `pymongo.uri_parser.parse_uri(uri)["database"]`. Two URI shapes give driver database `autotester` while the guard sees something else, and the store constructs:
- `mongodb://h/autotester.x` : `parse_uri` -> database `autotester`, collection `x` (the driver splits `db.collection` at the first dot); guard sees `autotester.x`. Also `mongodb://h/AUTOTESTER.coll`, `mongodb://h/autotester.`, `mongodb://h/%61utotester.%78`.
- `mongodb://u:p#x@h/autotester` : `parse_uri` accepts `#` in the userinfo and returns database `autotester`; `urlsplit` cuts a fragment at the `#`, so the guard sees path `''`.
Repro: `python qa/evidence/mongo-store-u1/checker-b/probe2.py` prints `CONSTRUCTED` for all five (default-validate `parse_uri`, no network). Impact is bounded because the URI path is never used to pick the write database (`mongo_guard.py:232` is `[cfg.database]`; M5 holds), but M4(c) is a CRITICAL refusal and its falsifier is met. The cycle-1 fix only added percent-decoding, and `test_the_path_is_decoded_exactly_as_the_driver_decodes_it` (7 URIs) never includes a `.` or a `#`.
Remedy: parse the way the driver does without DNS (`scheme-free.partition("/")`, path before `?`, `unquote_plus`, then `split(".", 1)[0]`), or refuse any path containing `.` or any userinfo `#`; extend the parity test with a corpus that includes `.`, `#`, `?` in userinfo, trailing dot.

**F2 (M9, CRITICAL) - a URI password is echoed in an exception.** `mongo_guard.py:206` calls `urlsplit(uri)` from `:229`, outside the `try` at `:231-234` that strips driver text. For a netloc with a character whose NFKC form contains `/?#@:` (for example a fullwidth colon or fullwidth at-sign in the password) CPython raises `ValueError("netloc '<full netloc incl. user:password>' contains invalid characters under NFKC normalization")`. It escapes the constructor unwrapped. Repro: `python qa/evidence/mongo-store-u1/checker-b/probe5.py` -> `canary in str(e): True | in traceback text: True` for `mongodb://umesh:CANARY<U+FF1A>pw@h.example/` and the `<U+FF20>` variant. M9 falsifier ("canary URI password appears in ... exception text") is met. Note the other bad-URI case (`[h` -> `Invalid IPv6 URL`) does not leak. `test_a_malformed_uri_rejected_by_the_driver_never_echoes_itself` only exercises driver parse errors, not `urlsplit`.
Remedy: catch `ValueError` around `_uri_path_database` and raise `StoreConfigError` with fixed text `from None` (and prefer not to use `urlsplit` at all, see F1); add the NFKC canary to the M9 tests.

**F3 (M6 intent, CRITICAL group) - a method on every collection object returns the raw driver collection.** `mongo_guard.py:119` `InsertOnlyCollection._raw()` returns `_REGISTRY[self._store][0][self._name]`; with the real driver that is a `pymongo.collection.Collection`, and `.database.client[<any name>]` is then a client handle for any database. Repro: `probe1.py` section B calls `store.collection("projects")._raw()` (a bound method found by `dir()`) and writes a document into a foreign database through it while the spy still reports `['autotester']`; it also lists every zero-argument private method on store, collection and bucket that returns a non-primitive (only `_raw`). M6 says no attribute reachable by `__getattr__` or a `__dict__` walk returns a pymongo object; the walk in `tests/test_mongo_guard_surface.py:53-55` skips callables, so `_raw()` is invisible to it. Python cannot hide the module-private `_REGISTRY`/`_SEAM` (the manifest says so, point 5), but a method that hands out the driver object on every collection is gratuitous.
Remedy: make it a module-level function (`_raw_collection(store, name)`), not a method of the object, and extend the walk to call zero-argument private methods.
